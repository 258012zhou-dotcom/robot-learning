# AGILEX PIPER 部署速查

这是一份由历史真机检查汇总出的快速入门资料。用途是以后决定把策略部署到 PIPER 时，快速了解设备、接口、已验证事实和已知问题。原 024、025 实验脚本、测试、配置和逐次记录已从当前项目删除；原 026 只完成准备与诊断，没有执行主动关节运动。详细历史仍可从 Git 提交 `52d01cb` 恢复。

## 设备与历史环境

| 项目 | 历史记录 |
| --- | --- |
| 设备 | AGILEX PIPER，6 关节机械臂；完整序列号不写入仓库 |
| 通信 | SocketCAN `can0`，历史 bitrate 为 1,000,000 |
| SDK | `piper_sdk 0.6.1`，历史 Python 环境为 `xvla` |

这些是 2026 年 9 月的历史环境，不是永久配置。未来部署前重新读取固件、SDK 版本、CAN 状态和当前反馈。

## 接口和单位

- 关节位置反馈：原始整数单位为 `0.001°`；弧度换算为 `raw × 0.001 × π / 180`。
- 设备查询的角度限位：原始单位为 `0.1°`，与当前位置反馈比例不同。
- 夹爪位置反馈：原始单位为 `0.001 mm`，换算为米是 `raw × 1e-6`。
- `ConnectPort(piper_init=False)`：历史上用于只启动接收，不执行 SDK 初始化查询。
- `EnableArm(7)`：请求六轴使能；使能、发送位置目标、停止和失能是四种不同操作。
- `JointCtrl(...)`：六轴目标必须一起发送，单位为 `0.001°`。只想改变一个关节时，其余五轴也必须使用经过核对的目标，不能随手填零。

## 真机已验证的内容

- 能通过 SDK 读取六轴角度、夹爪位置、使能状态和机械臂状态。
- 完成过一次参数查询和单臂固件回复交叉核对。
- 完成过一次六轴使能反馈验证：六轴由未使能变为已使能，模式仍为待机，检查的故障标志正常；现场未观察到明显运动或异响。
- 没有验证主动关节运动、位置保持精度、失能、Watchdog、通信中断保护或快速停止的真机效果。

## 已知设备特点和代码问题

- 一次重新上电后的稳定反馈为 `[-0.349, -1.895, 1.015, 0.391, 24.144, 0]°`。J2、J3 略超出设备报告范围，用户确认这是该机械臂的已知偏差；未设置软件补偿或重新标零。
- 当时读取到的关节超限、通信异常和驱动故障标志均为正常。未使能时不报错不能证明控制器会接受相同的运动目标。
- SDK 0.6.1 的软件关节限位默认关闭；启用后会裁剪目标和反馈，可能掩盖原始值。
- 历史 ACT 适配会把越界关节裁剪到限位。当前 J2、J3 若直接进入该逻辑，会被裁成 0°，因此所谓“只动 J1”也可能改变 J2、J3 目标。
- SDK `JointCtrl` 文档曾把 J6 写为 ±120°，设备查询返回 ±180°。未来部署必须选择并记录实际采用的边界来源。
- 夹爪曾返回 `homed=false`。这只说明当时反馈状态，不能单独据此判断必须标定。

## 停止、断开和 ACT 退出

以下是对 SDK 0.6.1 和历史 ACT 副本的源码分析，不能替代未来版本的重新核对：

| 接口或流程 | 源码行为 |
| --- | --- |
| `EmergencyStop(0x01)` | 发送快速停止请求；历史实验未验证真机效果 |
| `EmergencyStop()` | 默认参数为 0，表示无效 |
| `DisconnectPort()` | 关闭接收线程和 CAN 连接，不发送停止或失能 |
| `ResetPiper()` / `EmergencyStop(0x02)` | SDK 警告会失电下落，不能当作保持当前位置的停止方式 |
| 历史 ACT `robot.disconnect()` | 先发送安全位置目标，等待约 5 秒，再失能 |

用户报告停止和通信断开后保持力矩；这是现场经验，没有测量保持精度或运动中断线后的目标处理。该设备没有独立物理急停按钮，末端示教按钮不能当作急停。

## 未来部署检查顺序

1. 核对机械臂、固件、SDK、CAN 连接和当前控制程序，不直接复用历史版本假设。
2. 只读检查六轴反馈、时间戳、状态、使能和故障位，确认观察顺序及单位。
3. 审计策略的数据契约：相机名称与尺寸、关节顺序、弧度或角度、绝对或增量动作、夹爪语义、控制频率和 Action Chunk 执行方式。
4. 明确 J2/J3 偏差如何进入归一化、限位和动作目标；不得用静默裁剪掩盖。
5. 检查部署代码的启动、停止、异常和退出路径，尤其避免历史 ACT 的自动安全位和失能流程与当前需求冲突。
6. 先做不连接设备的输入输出预览，再做只读集成，最后才设计小范围真机验证。

这份速查帮助定位部署前必须重新验证的接口，不代表 PIPER 已经具备策略部署条件。

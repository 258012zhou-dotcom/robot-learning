# 实验 055：速度动作的单位接线边界

## 目标与原理

实验 [054](../054_route_conditioning/README.md)的条件化 BC 输出 `[vx, vy]`，单位是 `m/s`。二维点机器人环境的控制周期为 `dt=0.1 s`，因此正确的一步位置变化是 `速度 × dt`。例如 `vx=0.6 m/s`，一步应走 `0.06 m`。

这次冻结 **同一个 054 checkpoint**，不重新训练，也不改变场景、指令或时限。只改变策略到环境之间的接线：正确组原样传递速度；错误组误把速度先乘一次 `dt`，再交给仍然期待速度的环境。环境会再乘一次 `dt`，使实际一步位移变成 `速度 × dt²`。错误组的动作形状与范围仍合法，因此普通的 shape/限幅检查不能发现这个单位错误。

## 验证协议

仍使用 053 的 40 个验证场景与 40 个测试场景，每个场景分别请求上下路线，共每组 80 次请求；预测 8 步、执行 4 步、Episode 最多 80 个 `0.1 s` 控制步。脚本核对数据和 checkpoint 来源哈希，正确组逐请求复现实验 054；两组同场景同指令的首个原始策略输出必须相同。每步检查：实际位置变化等于**送入环境的动作**乘 `dt`，并记录模型原始速度、适配层输出与真实位移。没有用测试成功率选择缩放系数。

新增单元测试的对象是速度适配层与环境的一步积分。输入 `0.6 m/s` 时，正确传递应移动 `0.06 m`；重复乘 `dt` 后应移动 `0.006 m`。若失败，说明实验并未隔离单位接线错误。运行：

```bash
PYTHONPATH=src /home/zxd/miniconda3/envs/robot_learning/bin/python -m pytest -q tests/test_velocity_command_adapter.py tests/test_route_conditioning.py
PYTHONPATH=src /home/zxd/miniconda3/envs/robot_learning/bin/python experiments/055_velocity_unit_boundary/run.py
```

## 实际结果与解释边界

单元测试 `7 passed`；连同共享片段、路线、场景与轨迹测试复验为 `55 passed, 1 warning`，警告是未注册 Gymnasium 环境的渲染模式检查。测试集实测：

| 接线方式 | 首步平均水平位移 | 到达且遵循路线 | 碰撞 | 超时 |
| --- | ---: | ---: | ---: | ---: |
| 正确传递速度 | `0.06606 m` | 80/80 | 0 | 0 |
| 重复乘 `dt` | `0.006606 m` | 0/80 | 0 | 80/80 |

这里的 `0/80` **不是**精细的学习算法鲁棒性结果：错误组最大水平速度仅 `0.1 m/s`，80 步共 8 秒，即使每步都以最大正向速度走，水平最多移动 `0.8 m`。这 40 个测试场景里，考虑到目标半径后所需的**最小**水平位移仍约 `2.254 m`，因此 80 步内不可能到达。验证集也呈相同的 80/80 对 0/80。结论仅是：动作单位契约错了，即使模型权重、输入场景和动作 shape 都没变，闭环任务也会机械性地不可达；不能用这组 0 分去声称模型本身差。

输出 `results.json` 保存在 Git 忽略的 `outputs/055_velocity_unit_boundary/`。这是无接触、无相机的合成二维仿真，测试场景也已在 053/054 中使用过；不是新盲测、论文复现或真实机器人结论。本实验只处理**单位重复换算**，不处理时间戳错位、动作延迟或速度/位置控制器互换。

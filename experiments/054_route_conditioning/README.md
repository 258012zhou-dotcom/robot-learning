# 实验 054：路线元数据何时成为可执行指令

## 目标与原理

实验 [053](../053_diffusion_two_route_foundation/README.md)为同一二维绕障场景提供两条成功示范，数据中 `policy_id=0` 表示下绕，`policy_id=1` 表示上绕。原始 7 维 BC 只接收机器人位置、目标与障碍信息，**路线 ID 不在输入中**；因此它可能到达目标，却不能随外部请求切换路线。

本实验把 `policy_id` 转成教学用的“路线指令” `c=-1/+1`，作为第 8 个输入，训练一个条件化片段 BC；执行时在同一场景分别给出上下指令。这里人为假设指令在执行前就已知且始终不变。它不是自然语言理解，也不是把路线由模型自动推断出来。

## 协议和检查

- 完全复用 053 的 `dataset.npz` 与场景划分，核对数据哈希；同一场景的两条路线不能跨训练/验证/测试。训练观察归一化只拟合训练集，第 8 维为 `-1/+1`。片段不跨 Episode，尾部用掩码排除补齐动作。
- 条件化 BC 和冻结的非条件化 BC 采用相同训练种子 42、隐藏层宽度 64、60 个 epoch、8 步预测/4 步执行、训练批次与优化参数。唯一计划增加的策略输入是路线指令；因此条件化模型输入维度为 8，非条件化为 7。以验证集片段 MSE 选条件化模型，之后评价测试集。
- 每个测试场景请求下绕和上绕各一次。除“是否到达”外，还用轨迹越过障碍中心 x 位置时的 y 坐标判断实际走哪一侧。**联合成功**要求既到达目标又走了指定侧；若碰撞前未穿过中心，路线记为未知，不算遵循指令。对照 BC 不接收请求，因此同一场景两次执行应完全相同。

单元测试检查：相同观察配不同指令会产生不同的第 8 维；验证/测试不参与归一化；场景不能跨 split；策略 reset 后按新指令预测；上下专家轨迹的侧别判定正确，并区分直穿障碍与尚未越过障碍。失败意味着“标签可用性”或联合指标不可信。运行命令：

```bash
PYTHONPATH=src /home/zxd/miniconda3/envs/robot_learning/bin/python -m pytest -q tests/test_route_conditioning.py
PYTHONPATH=src /home/zxd/miniconda3/envs/robot_learning/bin/python experiments/054_route_conditioning/run.py
```

## 实际结果与限制

单元测试 `5 passed`；连同共享片段、场景与轨迹测试复验为 `53 passed, 1 warning`，警告是未注册 Gymnasium 环境的渲染模式检查。条件化模型在第 60 个 epoch 取得最低验证片段 MSE，测试片段 MSE 约 `0.00188 (m/s)^2`。验证与测试集均各有 40 场景 × 2 路线请求；测试结果：

| 策略 | 到达目标 | 按指定侧绕行 | 两者同时成功 | 碰撞 |
| --- | ---: | ---: | ---: | ---: |
| 8 维、接收路线指令的 BC | 80/80 | 80/80 | 80/80 | 0/80 |
| 原 7 维、不接收指令的 BC | 74/80 | 37/80 | 37/80 | 6/80 |

例如测试场景 seed 20000：条件化 BC 请求下绕与上绕时，第一动作纵向速度约为 `−0.491` 与 `+0.378 m/s`，最终都按要求到达；非条件化 BC 对两个请求均输出同一条上绕轨迹，因而下绕请求不合格。**到达率不能替代指令遵循率**。原 BC 在 40 场景中成功 37 个，这里为每个场景重复两个请求，故到达数为 74/80、联合成功最多只能是 37/80。

这是单训练种子、同分布、合成速度控制点机器人的**机制验证**，不是复杂任务、语言指令、真实机器人或论文复现。额外输入维度会改变模型参数与初始化；虽然其余预算相同，不能仅据此宣称某种算法普遍更好。更重要的是，这个 `policy_id` 原本只是脚本专家的路线元数据，只有在本实验明确把它定义为执行前可提供的任务指令时，才具有条件化训练意义。若部署时拿不到可靠的指令标签，就不能照搬此结论。权重和逐请求记录在 Git 忽略的 `outputs/054_route_conditioning/`。

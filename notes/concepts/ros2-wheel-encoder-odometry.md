# ROS 2 编码器与差速轮里程计

## 快速复习

- 编码器（Encoder）输出的是轮子累计计数，不是机器人真实位置。
- 计数差乘以每 tick 路程，得到左右轮在一个采样周期内的路程 `d_l` 和 `d_r`。
- 差速轮里程计用左右轮路程估计平面位姿 `(x, y, θ)`：两轮相同则直行，两轮相反则原地转动，其余情况沿圆弧运动。
- `/wheel_ticks` 是原始测量，`/odom` 是积分得到的状态估计；真实机器人还需要面对量化误差、轮径误差和打滑。
- 标准 TF 关系是 `odom → base_link`。同一时刻不能再由另一个节点发布不同父坐标系到 `base_link`。

## 从编码器计数到轮子路程

设轮子半径为 `r`，每圈编码器计数为 `N`，某段时间内计数变化为 `Δn`：

```text
每 tick 角度 = 2π / N
轮子转角     = 2πΔn / N
轮子路程     = 2πrΔn / N
```

实际驱动通常提供累计计数，因此算法需要保存上一帧计数：

```text
Δn = current_count - previous_count
```

第一帧没有 previous count，只能建立基准，不能推断此前发生的运动。负的计数变化表示轮子反向旋转。

## 差速轮运动模型

设左右轮增量路程为 `d_l`、`d_r`，两轮中心距离为 `b`：

```text
中心路程：d_s = (d_l + d_r) / 2
航向变化：d_θ = (d_r - d_l) / b
```

三种典型情况：

- `d_l = d_r`：`d_θ = 0`，机器人直行。
- `d_l = -d_r`：`d_s = 0`，机器人原地旋转。
- 其他情况：机器人以瞬时转动中心为圆心沿圆弧运动。

圆弧情况下，转弯半径 `R = d_s / d_θ`，机器人自身坐标系中的增量为：

```text
body_x = R sin(d_θ)
body_y = R (1 - cos(d_θ))
```

再根据更新前的航向，把这个增量旋转到 `odom` 坐标系并累加到 `(x, y)`。航向最终归一化到 `[-π, π)`，避免角度无限增长。

## ROS 2 数据流

当前项目的数据流为：

```text
wheel_encoder_publisher
        │  point_robot_interfaces/msg/WheelTicks
        ▼
    /wheel_ticks
        │
        ▼
   odometry_node
      ├── /odom  [nav_msgs/msg/Odometry]
      └── odom → base_link  [TF]
```

`WheelTicks` 包含采样时间和左右轮累计计数。使用自定义消息是为了明确表达“原始 tick”语义；某些真实驱动也可能改用 `sensor_msgs/JointState` 发布轮子角度。

`nav_msgs/msg/Odometry` 同时包含：

- `header.frame_id = odom`：位姿相对于哪个坐标系。
- `child_frame_id = base_link`：被估计的机器人机体坐标系。
- `pose`：位置与姿态。
- `twist`：机体前向线速度和绕 z 轴角速度。

二维航向 `θ` 写入三维姿态时使用绕 z 轴旋转的四元数：

```text
q_z = sin(θ / 2)
q_w = cos(θ / 2)
```

当前节点用相邻消息时间戳计算 `dt`，再由相邻位姿变化估计线速度和角速度。第一帧只初始化计数和时间，因此速度为零。

## 坐标系与数据含义

需要严格区分三种量：

- 编码器计数：传感器测量值。
- 里程计位姿：从轮子运动不断积分得到的估计值。
- Ground truth：机器人真实位姿，真实系统通常不能被直接、无误差地获得。

`odom` 适合表示短期连续、但会逐渐漂移的局部坐标系。未来加入定位或传感器融合后，常见坐标树是：

```text
map/world → odom → base_link → sensor frames
```

当前旧位置演示还可以发布 `world → base_link`。它不能和 `odom → base_link` 同时作为正式位姿来源，否则 TF 中的 `base_link` 会出现多个父节点。

## 当前项目证据与边界

纯 Python 测试覆盖了整圈、半圈、反向计数、累计计数差、直行、原地旋转、圆弧运动、角度归一化、首帧初始化和多次累计，共 12 项。ROS 2 实际运行还验证了：

- `WheelTicks` 自定义消息可以通过 `/wheel_ticks` 传输。
- 编码器发布者与里程计节点形成 1 对 1 Topic 通信。
- 两轮同增量时 `/odom` 的 x 增长，y 和航向基本不变。
- 两轮增量不同时，位置和航向随圆弧运动变化。
- `odom → base_link` 可以通过 TF2 查询。
- 完整工作空间测试汇总为 41 tests、0 errors、0 failures、1 skipped。

这些结果来自确定性的理想软件模拟，不代表真实硬件精度。尚未加入计数量化噪声、轮径标定误差、左右轮不一致、轮胎打滑、协方差和外部传感器校正；这些因素都会使纯轮式里程计随时间漂移。

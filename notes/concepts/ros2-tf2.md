# ROS 2 TF2 坐标系统

## 快速复习

- Frame（坐标系）定义观察位置和方向的参考基准。
- TF2 用一棵有方向的坐标树维护父子 Frame 之间的变换。
- 变换包含平移、旋转、父坐标系、子坐标系和时间戳。
- 静态变换发布到 `/tf_static`，动态变换持续发布到 `/tf`。
- 点的坐标转换遵循 `p_parent = R p_child + t`，存在旋转时不能只把坐标直接相加。
- TF2 可以沿坐标树自动组合多级变换，也可以计算反向变换。

## Frame 与坐标树

同一个物体在不同坐标系中会有不同坐标。例如摄像头测得目标在自身前方 1 米，这个结果属于 `camera_link`，不能直接当成世界坐标。

当前练习建立过：

```text
world
└── base_link
    └── camera_link
```

`world` 是全局参考，`base_link` 是机器人底座，`camera_link` 是安装在机器人上的摄像头。TF2 要求每个子 Frame 只有一个直接父 Frame，否则同一坐标系会出现互相冲突的定义。

## 平移、旋转与齐次矩阵

子坐标系中的点转换到父坐标系时：

```text
p_parent = R p_child + t
```

其中 `R` 是旋转矩阵，`t` 是子坐标系原点在父坐标系中的位置。齐次矩阵把两者写成一个变换：

```text
T = [ R  t ]
    [ 0  1 ]
```

当 `world → base_link` 平移为 `[1.0, 0.5, 0.0]`、`base_link → camera_link` 平移为 `[0.2, 0.0, 0.3]` 且都没有旋转时，组合结果为 `[1.2, 0.5, 0.3]`。

当 `camera_link` 绕 z 轴旋转 90° 时，其四元数约为 `[0, 0, 0.707, 0.707]`。摄像头坐标中的 `[1, 0, 0]` 先被旋转为世界方向的 `[0, 1, 0]`，再加摄像头原点平移，得到 `[1.2, 1.5, 0.3]`。

## 静态变换与动态变换

`static_transform_publisher` 用于不随时间变化的安装关系，例如底座到摄像头。静态变换显示为 `At time 0.0`，并通过 `/tf_static` 发送。

动态关系随机器人运动持续更新。当前项目的 `position_tf_broadcaster`：

1. 订阅 `/point_robot/position`。
2. 创建带当前时间戳的 `TransformStamped`。
3. 设置父 Frame 为 `world`、子 Frame 为 `base_link`。
4. 将位置消息写入平移，使用单位四元数表示无旋转。
5. 通过 `TransformBroadcaster` 发布到 `/tf`。

实测中，`tf2_echo world base_link` 的时间戳持续变化，x 坐标在约一秒内从 `35.3` 增加到 `35.8`，与默认速度 `0.5 m/s` 一致。

## 时间与缓存

动态 TF 不只回答“坐标系在哪里”，还回答“某个时刻在哪里”。TF2 会缓存一段历史变换，以便传感器消息按自己的时间戳查询对应变换。若查询时间早于缓存、晚于最新数据，或坐标树不连通，查询会失败。

`view_frames` 实测得到 `world → base_link`，平均频率约 `10.196 Hz`、缓存跨度约 `5.1 s`。`tf2_echo` 刚启动时短暂报告 Frame 不存在，是因为 DDS 发现和第一条 TF 尚未到达；随后能持续输出就不属于故障。

## 当前边界

当前系统只把二维位置广播为 `world → base_link`，方向固定且没有真实里程计、传感器时间同步或定位误差。TF2 基础已经通过静态链、旋转、多级组合、动态广播和坐标树检查完成第一轮验证；后续将在 URDF、RViz、里程计和状态估计中继续应用。

# Python 可靠软件边界

## 快速复习

- 类型提示说明预期，不会在运行时自动拦截错误数据。
- 外部输入先检查类型、形状、有限性、单位与取值范围，再改变状态。
- 抛出异常不一定意味着安全：还要决定保留旧状态，还是清空危险命令。

## 输入检查到底检查什么

| 层次 | 例子 | 只检查上一层为什么不够 |
| --- | --- | --- |
| 类型 | dt 是数值，steps 是整数 | `True` 在 Python 中也是 int 的子类，未必符合业务意图 |
| 形状 | 位置是 `(2,)`，轨迹是 `(T,2)` | 都是数组，不代表轴含义相同 |
| 有限性 | 拒绝 NaN、正负无穷 | `NaN <= 0` 为假，仅检查正负会漏掉它 |
| 范围与语义 | dt>0，角度用弧度，位置注明坐标系 | 类型与形状正确也可能把度数当弧度 |

JSON、命令行、传感器消息等输入应先通过这些检查，再进入核心计算。

项目中 `PointRobotConfig.from_mapping()` 将 JSON 字典转换为字段明确的配置：缺字段、二维形状错误、非法 `dt` 或 `steps` 会尽早抛出清楚的 `ValueError`。核心数值函数仍保留自己的输入检查，形成两层保护。

日志记录配置、关键参数和结果；异常应提供上下文或可恢复措施，不能用空的 `except` 隐藏错误。

## 有状态对象：先验证，再修改

```text
读取候选值 → 完整验证 → 更新状态 → 执行计算
```

项目的 Gymnasium 环境拒绝非法 reset 时保留原来的物理状态、随机序列与延迟队列，让调用者可以纠正输入后继续；安全监督器则在非法速度到来时清空旧速度，让系统先停止。二者都合理，区别在于失败后最安全、最明确的状态是什么。

`@dataclass(frozen=True)` 只限制字段重新赋值，不会深度冻结字段中的 NumPy 数组或列表；如果确实要求数据不可变，还需要复制、只读数组或不可变容器。

## 跨线程边界

线程边界同样需要显式传递错误：实验 003 通过错误队列把生产者异常带回主线程，并用 `None` sentinel 结束消费者等待。外部输入、函数调用和线程通信都是需要验证或报告失败的边界。

# 测试、调试与可复现性

## 快速复习

- 测试是在明确输入下检查预期行为，不是“运行时没报错”。
- 代码规范、纯函数逻辑、模块通信和真实硬件是不同层次，不能相互替代。
- 复现要保留代码、环境、配置、数据、预处理和权重；seed 只是其中一项。

## 四种证据分别说明什么

| 类型 | 本项目例子 | 不能据此声称 |
| --- | --- | --- |
| 规范检查 | Flake8、文档字符串 | ROS 消息一定送达 |
| 单元测试 | 输入误差，检查 PID 输出限幅 | 真实电机会按命令停止 |
| 集成测试 | 启动 ROS 节点，发送指令并观察位置 | 操作系统失效时硬件仍能安全停车 |
| 实验评价 | 保留集成功率、RMSE、OOD 失败分析 | 一个 seed 代表普遍性能 |

pytest 收集 `tests/` 中的 `test_...` 函数并执行断言；参数化测试会按每组输入各运行一次。`python -m pytest -q` 表示使用当前 Python 运行 pytest，并简洁报告结果。项目统一入口 `./scripts/run_tests.sh` 检查 Conda 环境并禁用无关 ROS pytest 插件；ROS 工作空间另用 colcon 测试，根项目通过不等于 ROS 已测。

## 读一条断言的方法

先问“输入是什么、期望是什么、失败说明哪个约定不成立”。例如 `assert max(positions)-min(positions) < 1e-9` 是验证一段新采样的位置保持不变，不只是验证最新一条速度消息为零。

浮点比较用容差；遇到 `0.05000000000000002` 不要马上修改物理公式。非法输入测试不仅应断言抛异常，还要检查对象没有留下错误状态。

## 调试顺序

调试时在 VS Code 设置断点，暂停后观察变量；`F10` 执行下一行而不进入函数。先读失败用例和报错，再决定修改位置。

### 单独通过、全量失败：也可能是运行库冲突

本次检查中，模型保存测试单独运行通过，和仿真测试一起运行却出现 `CXXABI_1.3.15 not found`。错误信息指向系统 `libstdc++.so.6`，而 Matplotlib 需要 Conda 中较新的 C++ 运行库：先加载哪个库会影响同一进程中的后续导入。

`scripts/run_tests.sh` 会优先使用当前 Python 环境的 `lib/`（存在 `libstdc++.so.6` 时），只影响本次测试及其子进程。它不修改系统库、不写入 `.bashrc`，也不改变父终端的 ROS 环境。修复后已通过全量测试；不要靠调整测试顺序掩盖问题。

直接运行实验仍是独立入口；若出现同类错误，要先检查具体库路径，再对该进程设置运行库搜索路径，不把此设置无差别应用到所有环境。

## 复现需要保存什么

可复现实验需要同一份代码、环境、配置和随机种子：

```text
代码版本 + 环境/依赖 + 配置 + 数据与划分 + 预处理/词表 + 模型权重
                           ↓
             在新进程加载 → 复查预测与实验指标
```

项目证据：实验 001 记录配置、种子和轨迹统计；实验 002 用 `np.random.default_rng(seed)`，固定 `seed=42` 得到相同 RMSE。只存图片而不存配置和结果，无法可靠复查实验。

固定 seed 不保证不同硬件、依赖版本上的结果逐位相同，更不能证明统计稳健性。推理用 checkpoint 与恢复训练也不同：后者通常还要优化器、调度器、训练步数和随机状态。LoRA 只有增量，必须配套正确基础模型。

测试应覆盖正常结果、边界值和非法输入。并发测试优先使用 `Event`、队列和零间隔，而不是依赖精确 `sleep`；后者会因机器负载产生不稳定结果。

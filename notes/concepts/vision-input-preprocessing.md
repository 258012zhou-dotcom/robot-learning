# 具身智能视觉输入与预处理

## 快速复习

具身智能视觉输入的核心不是“会调用几个图像函数”，而是维护一条一致的数据与几何流水线：

```text
相机图像
→ 检查颜色、形状、类型和值域
→ Resize / Crop / Letterbox
→ 同步变换目标框、关键点和相机内参
→ 转为模型要求的 Tensor
→ Batch 和 Device
→ 保存可检查的结构化结果
```

当前项目使用的主要契约是：

```text
OpenCV：BGR + HWC + uint8 + [0, 255]
PyTorch：RGB + NCHW + float32 + [0, 1]
```

任何一项顺序或尺度错误，都可能让程序正常运行但模型结果错误。

## 图像数据契约

一张彩色图像至少包含四类信息：

- 空间尺寸：高度 `H` 和宽度 `W`。
- 通道顺序：例如 BGR 或 RGB。
- 内存布局：例如 HWC、CHW 或 NCHW。
- 数据类型和值域：例如 `uint8 [0,255]` 或 `float32 [0,1]`。

常见表示：

| 场景 | 典型形状 | 通道 | 类型和值域 |
| --- | --- | --- | --- |
| OpenCV 彩色图像 | `(H, W, 3)` | BGR | `uint8 [0,255]` |
| 单张 PyTorch 图像 | `(3, H, W)` | RGB | `float32` |
| PyTorch 批次 | `(N, 3, H, W)` | RGB | `float32` |
| 二值 Mask | `(H, W)` | 单通道 | `uint8`，通常为 0/255 |

`NCHW` 中的 `N` 是 Batch Size。即使只有一张图，许多模型仍要求形状为 `(1, C, H, W)`。

## Resize、Crop 与 Letterbox

直接把任意长宽比的图像缩放到正方形会发生几何拉伸。对于检测、关键点、深度和机器人空间推理，这种变形可能破坏目标比例。

Letterbox 的做法是：

1. 使用同一个比例缩放宽度和高度。
2. 在剩余区域补边，使输出达到模型要求的固定尺寸。

若原图宽高为 `(W, H)`，目标宽高为 `(W_t, H_t)`，理想缩放率为：

```text
s = min(W_t / W, H_t / H)
```

由于实际像素尺寸必须取整数，代码应记录最终的 `scale_x`、`scale_y` 和左上补边，而不是只依赖理论缩放率。

## 坐标必须同步变化

当像素经过缩放和补边后，目标框不能保留原坐标。对于点 `(x, y)`：

```text
x' = scale_x * x + padding_left
y' = scale_y * y + padding_top
```

对于 `(x, y, width, height)` 目标框：

```text
width'  = scale_x * width
height' = scale_y * height
```

逆变换用于把模型输入坐标系中的预测框还原到原图：先减去 Padding，再除以 Scale。

同一原则也适用于关键点、分割 Mask 和其他像素级标注。

## 相机内参也属于几何数据

针孔相机内参常写成：

```text
K = [[fx,  0, cx],
     [ 0, fy, cy],
     [ 0,  0,  1]]
```

其中 `fx, fy` 是像素单位焦距，`cx, cy` 是主点。经过 Resize 和 Padding 后：

```text
fx' = scale_x * fx
fy' = scale_y * fy
cx' = scale_x * cx + padding_left
cy' = scale_y * cy + padding_top
```

如果只改变图像而不更新内参，之后的深度反投影、三维定位和坐标变换都会使用错误几何关系。

## HSV Mask 基线

HSV 将颜色近似拆分为色相、饱和度和亮度。对于颜色明显的合成目标，可以使用颜色范围生成 Mask：

```text
BGR → HSV → inRange → 二值 Mask
```

OpenCV 的 8 位 HSV 中，Hue 通常使用 `[0,179]`，Saturation 和 Value 使用 `[0,255]`。这与直觉上的角度 `[0,360)` 不同。

对 Mask 查找外部轮廓后，可以过滤小面积噪声并选择最大目标，再用外接矩形得到 `(x, y, width, height)`。

这个方法的优点是简单、可解释、容易验证；缺点是依赖颜色和阈值，容易受光照、阴影、相似颜色和遮挡影响。它适合作为数据流基线，不是通用视觉感知方案。

## 面向模型的转换

从 OpenCV 图像到 PyTorch 输入通常需要：

1. BGR 转 RGB。
2. HWC 转 CHW。
3. `uint8` 转 `float32`。
4. 从 `[0,255]` 缩放到 `[0,1]`。
5. 增加 Batch 维，得到 NCHW。
6. 移动到 CPU 或 CUDA Device。

具体模型可能还要求按训练时使用的均值和标准差进行归一化。不能假设所有模型都只需要除以 255，应以模型权重对应的预处理配置为准。

## 验证层次

视觉流水线应同时保留三类证据：

- 单元测试：检查形状、类型、数值、坐标公式和异常输入。
- 结构化结果：记录变换参数、检测框、内参和 Tensor 契约。
- 人工可视化：检查 Mask、目标框、比例和补边是否符合直觉。

只看图片可能漏掉小的数值错误，只看测试也可能漏掉视觉语义错误，两者应结合。
